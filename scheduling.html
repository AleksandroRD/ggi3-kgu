Process Scheduling
1 / 3


Scheduling is resource managment of the most finite recource - time

Your computer seems to run dozens of programs at the same time, but a single CPU core can execute only one process at a time. The OS switches between processes so fast that it looks simultaneous.

The scheduler is the part of the operating system that decides which ready process gets the CPU next, and for how long.

First-Come, First-Served at a glance

The simplest scheduler there is: whoever arrives first gets the CPU first. It works like a single checkout line in a shop.

How it works

  • New processes join the end of the ready queue (a plain FIFO queue).
  • When the CPU is free, the scheduler takes the process at the front.
  • That process runs until it finishes or blocks for I/O. Nobody can interrupt it.
  • Then the next process in line gets its turn.

FCFS: strengths and weaknesses

Simple and predictable, but not efficient

Strengths

  • Very simple to implement.
  • Process starvation is not possible.
  • Minimal overhead: one context switch per process.

Weaknesses

  • Average waiting time are very high
  • Convoy effect: short jobs get stuck behind one long job.
  • Poor for interactive systems, because of terible responsiveness.

Shortest-Job-First at a glance

Think of the express lane in a supermarket: whoever has the smallest basket gets served first, even if they joined the line later.

How it works

  • Every process in the ready queue has a burst time, the size of its basket.
  • When the CPU is free, the scheduler picks the process with the shortest burst, not the oldest.
  • That process runs until it finishes. Nobody can interrupt it (non-preemptive).
  • If two processes tie, the one that arrived first goes first.

SJF: strengths and weaknesses

Fast on average, but unfair to long jobs

Strengths

  • Gives the lowest possible average waiting time for a non-preemptive algorithm.
  • Short jobs finish quickly, so the system feels responsive.
  • Higher throughput: more processes complete per unit of time.

Weaknesses

  • Starvation: a long job can wait forever while shorter jobs keep arriving.
  • Burst time must be known in advance. In practice it can only be predicted from past behaviour.
  • Still non-preemptive: a long job that is already running blocks everyone (the preemptive version is called SRTF).

Priority Scheduling at a glance

Think of a hospital emergency room: the patient in the worst condition is treated first, no matter who arrived earlier.

How it works

  • Every process gets a priority number. Here 1 is the highest and 4 the lowest.
  • When the CPU is free, the scheduler picks the ready process with the highest priority.
  • Processes with the same priority are served in FCFS order.
  • The running process is not interrupted (non-preemptive version).

Priority Scheduling: strengths and weaknesses

Important work goes first, but low priority can wait forever

Strengths

  • Critical and time-sensitive processes get the CPU first.
  • Flexible: priority can reflect importance, deadlines or resources.
  • Widely used in real operating systems (e.g. system tasks over background jobs).

Weaknesses

  • Starvation: low-priority processes may never run while high-priority ones keep arriving.
  • Fix: aging, slowly raising the priority of processes that wait a long time.
  • Priority alone ignores burst time, so average waiting time can be worse than SJF.

Round Robin at a glance

Think of friends sharing one game console: everyone plays for a fixed turn, and whoever is not finished goes to the back of the line.

How it works

  • The ready queue is a plain FIFO line, like in FCFS.
  • The first process runs for at most one time quantum (a fixed slice of CPU time).
  • If it is not finished when the quantum ends, it is preempted and goes to the back of the queue.
  • Then the next process gets its turn, so everyone gets the CPU regularly.

Round Robin (RR)

Each process gets the CPU for at most one time quantum. If it is not finished, it goes to the back of the queue and the next one runs. Like taking turns on a shared game console.

Round Robin: strengths and weaknesses

Fair and responsive, but it pays for it in context switches

Strengths

  • Fair: every process gets the CPU regularly, so starvation is not possible.
  • Good response time, which suits interactive and time-sharing systems.
  • Simple to implement, and short jobs are not stuck behind a long one for long.

Weaknesses

  • Many context switches add overhead, especially with a small quantum.
  • The quantum is hard to choose: too large behaves like FCFS, too small wastes time on switching.
  • Average waiting and turnaround time are often higher than in SJF.

Completely Fair Scheduler at a glance

Think of a teacher who always helps the student who has received the least attention so far. Nobody is left waiting for long.

How it works

  • Each process tracks its vruntime: the CPU time it has received, scaled by its weight.
  • The scheduler always runs the process with the smallest vruntime (the leftmost node of a red-black tree).
  • It runs for a slice of the target latency, split by weight, then goes back into the tree with a larger vruntime.
  • A lower nice value means a higher weight: vruntime grows slower, so that process gets more CPU.

Completely Fair Scheduler (CFS)

The process with the smallest vruntime runs next. The queue is sorted by vruntime, so the leftmost box (closest to the CPU) is always next. Badges show each process's nice value; lower nice means more CPU share.

CFS: strengths and weaknesses

The Linux default for normal processes since kernel 2.6.23

Strengths

  • Fair: CPU share is proportional to weight, and nobody starves.
  • Needs no fixed quantum: the slice adapts to the number of running processes.
  • Scales well: picking the next process in a red-black tree takes O(log n).

Weaknesses

  • More complex than the classic algorithms.
  • No hard real-time guarantees, so Linux uses separate real-time classes.
  • With many processes the slices get tiny, so a minimum granularity is needed to limit context switches.
